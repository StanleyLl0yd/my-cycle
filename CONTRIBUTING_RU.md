# Участие в разработке My Cycle

[English](CONTRIBUTING.md) | [Русский](CONTRIBUTING_RU.md)

Предложения и изменения приветствуются, если они соответствуют текущей концепции My Cycle: небольшого приватного офлайн-трекера менструального цикла.

## Перед внесением изменений

Если вы исправляете ошибку, создайте issue, если проблема ещё не описана. Крупную новую функцию или изменение поведения лучше сначала обсудить в issue.

Учитывайте основные ограничения проекта:

- информация о цикле и фертильности должна явно оставаться расчётной;
- конфиденциальность и локальное хранение данных являются базовыми требованиями;
- аккаунты, облачная синхронизация, аналитика, реклама и функции, требующие сети, не входят в текущую концепцию версии 1.0.0 и не должны добавляться без отдельного решения по проекту.

## Требования для разработки

- JDK 21
- Android SDK 36
- Gradle 8.13

В репозитории сейчас нет `gradle-wrapper.jar`, поэтому для проверок из командной строки требуется установленный Gradle 8.13.

Перед созданием pull request выполните:

```bash
gradle assembleDebug test
gradle lint
```

Если изменение затрагивает release-сборку, также выполните:

```bash
gradle assembleRelease
```

## Pull request

1. Сделайте fork репозитория или создайте рабочую ветку.
2. Один набор изменений должен решать одну задачу или добавлять одну функцию.
3. При изменении логики определения цикла или прогнозов добавляйте или обновляйте тесты.
4. Пользовательский текст храните в Android string resources, а не непосредственно в Compose-коде.
5. Если меняется видимое пользователю поведение, обновляйте документацию.
6. В pull request кратко опишите, что изменено и зачем.

## Локализация

Английский язык является языком интерфейса по умолчанию. Русский поддерживается как дополнительная полная локализация.

При добавлении или изменении текста интерфейса:

- обновляйте `app/src/main/res/values/strings.xml`;
- обновляйте `app/src/main/res/values-ru/strings.xml`;
- при работе с формами множественного числа обновляйте оба файла `plurals.xml`;
- учитывайте ограниченное место на небольших экранах.

Для документации проекта поддерживайте синхронность основного английского файла и его версии `_RU`, где она предусмотрена.

## Стиль кода

- Следуйте соглашениям Kotlin.
- Предпочитайте небольшие функции с понятными именами.
- Не размещайте видимый пользователю текст непосредственно в коде.
- Сохраняйте существующее разделение между данными, доменной логикой и Compose UI.
- Не добавляйте новые зависимости без явной пользы для приложения.
